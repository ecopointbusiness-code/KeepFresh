Indicator Unit: Wiring Guide

ESP32 + 3.5″ SPI TFT + traffic-light LED module + buzzer

1. What you need

  • ESP32 dev board (30-pin or 38-pin, with USB cable)
  • 3.5″ SPI TFT display, ILI9488 driver (the module with 14 pins, with or without touch)
  • Traffic-light LED module (pins labelled G, Y, R, GND)
  • Buzzer: active buzzer module (pins S, +, −) or a bare active buzzer
  • Jumper wires (female-to-female for modules), breadboard optional
  • Only if your buzzer is a bare 5 V part: one NPN transistor (2N2222 or S8050) and one 1 kΩ resistor
Before you start: unplug the USB cable while wiring. Use the ESP32’s 3V3 pin for the logic of every module unless the part says 5 V only. Never connect a GPIO pin directly to 5 V.

Bare buzzer (just two wires, no little circuit board)? An ESP32 pin can safely give only about 12 mA, and many buzzers draw more. Wire: GPIO 33 → 1 kΩ resistor → transistor base. Transistor emitter → GND. Buzzer (+) → 5 V (VIN pin), buzzer (−) → transistor collector.

4. Software setup

  1. Install the Arduino IDE and add ESP32 support (Boards Manager → esp32 by Espressif). Choose board ESP32 Dev Module.
  2. Library Manager: install TFT_eSPI and ArduinoJson (version 7).
  3. Open the TFT_eSPI library folder (Documents/Arduino/libraries/TFT_eSPI) and edit User_Setup.h. Turn on only this driver and these pins:
#define ILI9488_DRIVER

#define TFT_MISO 19
#define TFT_MOSI 23
#define TFT_SCLK 18
#define TFT_CS   15
#define TFT_DC    2
#define TFT_RST   4

#define SPI_FREQUENCY       27000000
#define SMOOTH_FONT
  1. Open firmware/keepfresh_esp32/keepfresh_esp32.ino and fill in WIFI_SSID, WIFI_PASS, SERVER and DEVICE_KEY.
  2. Admin portal → Devices → Register device: copy the API key into DEVICE_KEY and give the device code to the customer.
  3. Plug in USB, press Upload. If it hangs at “Connecting...”, hold the BOOT button on the ESP32 until upload starts.
SERVER must be reachable from the ESP32. On a home network use your PC’s Wi-Fi address with the port (for example http://192.168.1.5:3000). The sketch uses HTTPS, so for plain http:// testing change WiFiClientSecure to WiFiClient in poll(), or deploy the server behind HTTPS.

5. Testing, step by step

  1. Power on. The screen shows Connecting to Wi-Fi... then the KeepFresh status.
  2. In the admin portal, open Devices and press Test. Within 30 seconds the three lights cycle green, yellow, red.
  3. Press Buzz. The buzzer beeps three times.
  4. In the customer app, link the unit under Profile → Indicator Unit with the device code. Add an item that expires soon and watch the light and screen change.

5b. What the screen shows

  • Status banner: ALL FRESH (green), USE SOON (yellow), USE TODAY or DISCARD NOW (red), with how many items need attention.
  • Four counters: Fresh, Use soon, Use today, Expired.
  • Items that need attention: the exact product name, quantity, and days left (for example Chicken breast: TOMORROW or Milk: EXPIRED 2d), most urgent first.
  • Bottom bar, rotating every 5 seconds: a cooking tip that uses the item about to spoil, any advisory sent by the admin, and total items with “updated Ns ago”. It turns red if the server cannot be reached.
  • Top bar: household name, clock, and Wi-Fi strength.
  • Not linked yet: the screen shows the device code and how to link it in the app.
  • BOOT button (on the ESP32 board, no wiring): press once to mute the buzzer for 1 hour, press again to un-mute. If something stays critical, the buzzer reminds you every 30 minutes unless muted.

6. Troubleshooting

ProblemCheck
Screen stays whiteRST and CS wires, ILI9488_DRIVER enabled, backlight LED pin on 3V3, User_Setup.h saved in the correct TFT_eSPI folder
Colors wrong or mirroredTry #define TFT_RGB_ORDER TFT_BGR, or change setRotation(1) to 3
A light never turns onSwap that signal wire to another GPIO and update PIN_G/PIN_Y/PIN_R; confirm GND is shared
Buzzer silent or weakActive (not passive) buzzer? Use the transistor circuit for bare buzzers
Upload failsHold BOOT while uploading; try another USB cable (some are charge-only)
